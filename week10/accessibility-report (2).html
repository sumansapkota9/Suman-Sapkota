1. Problem and purpose

The instructor asked for keyboard accessibility on the new Week 10 pages: a "Skip to main content" link that appears on the first Tab press, and pressing Enter on it must take the keyboard straight to the main content, without going through every navigation link first.

The new pages (Week 10 hub, portfolio, Book Search, Git exercise and the custom 404 page) had no skip link at all, and their <main> elements were not focusable targets. This revision adds the same skip-link behaviour to all five pages.

2. Changes made

AreaBeforeAfter
First keyboard stop No skip link on any Week 10 page; Tab started at the first link or button. "Skip to main content" is the first link, placed right after the opening <body> tag.
Main target <main> was not focusable. One <main id="main" tabindex="-1"> target on every page.
Activation Nothing to activate. A small click handler moves keyboard focus to #main. Enter on the link activates it natively, and the #main fragment stays as a fallback.
Visibility — The link sits off-screen until focused, then appears at the top left with a yellow focus outline, so it never disturbs mouse users.

3. Keyboard test procedure

  1. Open a page fresh, with focus in the page.
  2. Press Tab: "Skip to main content" becomes visible and focused.
  3. Press Enter: focus moves to the main-content landmark.
  4. Press Tab again: focus continues to the first link or control inside the main content, skipping the navigation above it.

Tab moves between controls; Enter activates a link. The skip link keeps this standard keyboard behaviour — Tab alone does not activate it.
